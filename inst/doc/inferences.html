Inference with specification curve analysis

In their paper, Simonsohn et al. (2020) propose a third step within the logic of specification curve analysis, which refers to conducting inference tests across the entire range of the specification curve. This step aims to address the following question: Considering the full set of reasonable specifications jointly, how inconsistent are the results with the null hypothesis of no effect?

We have been contemplating the implementation of this third step in our package. Until recently, we have concluded that there remains significant uncertainty regarding when such joint inferences are appropriate (see, for example, the recent discussion by Del Giudice & Gangestad, 2021), who highlight:

“In principle, multiverse-style analyses can be highly instructive. At the same time, analyses that explore multiverse spaces that are not homogeneous can produce misleading results and interpretations, lead scholars to dismiss the robustness of theoretically important findings that do exist, and discourage them from following fruitful avenues of research. This can hinder scientific progress just as much as the proliferation of false, unreplicable findings does” (p. 2).

The issue is as follows: Multiverse or specification curve analyses can serve different purposes. In the simplest form, it may serve to explore and discover differences in effect sizes that relate to specific theoretical or analytical decisions. Yet, the method is also suggestive of being a “somehow better approach to testing a relationship”. The aim of this second purpose, which is akin to a robustness test, is to exhaust the multiverse of truly arbitrary decisions in order to gain some sort of aggregate finding that can be use to refute or support a hypothesis. As Del Giudice and Gangestad point out very convincingly, however, it is often not straight-forward to decide whether specification is truly arbitrary (or in their terms: exhibits principled equivalence) compared to another specification. Yet, if this is not the case, running any inference tests is futile as “Just a few decisions incorrectly treated as arbitrary can quickly explode the size of the multiverse, drowning reasonable effect estimates in a sea of unjustified alternatives.” (Del Giudice & Gangestad, 2021, p. 2).

For these reasons, we have been, and continue to be, concerned that tools for such an inference test could be misused or lead to improperly conducted robustness tests. Nevertheless, due to frequent inquiries, we have integrated a function called infer_curve() in specr (since version 1.1.0). It implements the procedure described in the section “Inference with non-experimental data” of the paper by Simonsohn et al. (2020).

How it works

The idea behind this inference approach is that one forces the null on the data: for non-experimental data, Simonsohn et al. (2020, p. 1213) propose to modify the dependent variable of each specification such that the estimated effect becomes exactly zero, and then to draw bootstrap samples from these modified data. As the null hypothesis is true in these data by construction, the specification curves estimated in the bootstrap samples show what the curve would look like if there were no effect.

In infer_curve(), this works as follows:

  1. For every specification \(k\), the dependent variable is modified so that the null hypothesis is true by construction: \(y^*_k = y_k - b_k x_k\), where \(b_k\) is the estimate observed in that specification. Each specification thus gets its own modified dependent variable.
  2. \(N\) rows are drawn at random with replacement from the data set (with \(N\) being the number of rows of the data set). The same rows are used for all specifications, which preserves the dependence between them.
  3. Every specification is refitted on these rows with \(y^*_k\) as its dependent variable. Each specification keeps its own model, control variables, subset, and additions to the formula.
  4. Steps 2 and 3 are repeated many times (e.g., 1,000 times). This produces a distribution of specification curves that would be expected if all specifications had a true effect of zero.

Based on these curves, the observed specification curve can be tested with three test statistics:

  1. The median effect estimated across all specifications: is it more extreme than would be expected if all specifications had a true effect of zero?
  2. The share of specifications that obtain a statistically significant effect in the predicted direction: is it more extreme (higher) than would be expected if all specifications had an effect of zero?
  3. The aggregated z-value (Stouffer’s Z), which combines the p-values of all specifications: is it more extreme than would be expected if all specifications had an effect of zero?

Because the null is imposed by subtracting \(b_k x_k\) from the dependent variable, this procedure requires models that are linear in the dependent variable (e.g., lm, lmer, or glm with a gaussian family), numeric independent and dependent variables, and unstandardized estimates. infer_curve() checks this before resampling (by refitting every specification on its modified dependent variable, which has to yield an estimate of zero) and stops otherwise. For example, logistic regression models or structural equation models are not supported.

Setup specifications and run the specification curve analysis

We first run a standard specification curve analysis using the functions setup() and specr(). In this example, we investigate the relationship between two independent variables (x1 and x2, e.g., two alternative measures of the same construct) and the dependent variable y1, with different combinations of two control variables and in different subsets of the data.

specs <- setup(data = example_data,
   y = "y1",
   x = c("x1", "x2"),
   model = "lm",
   controls = c("c1", "c2"),
   subsets = list(group2 = c("female", "male")))

results <- specr(specs)

Refit the models under-the-null

Run the resampling procedure

To run the procedure, we simply use the function infer_curve(), which requires the results, the specification setup (or the data set), and the number of bootstrap samples that should be drawn. Simonsohn et al. (2020) use 500 samples. Here, we use 1,000 samples, which is a reasonable minimum for results that are reported. As the procedure relies on random sampling, we set a seed to make the results reproducible.

set.seed(42)
inference <- infer_curve(results, specs, n_samples = 1000)

For specifications fitted with lm, infer_curve() uses a fast least-squares routine that gives the same results as lm(), so that even several thousand bootstrap samples only take a few seconds. Other models are refitted with their original model function, which takes longer. In this case, the resampling can be parallelized by setting up a plan before running infer_curve() (see vignette("parallelization")), e.g.:

library(furrr)
plan(multisession, workers = 4)
inference <- infer_curve(results, specs, n_samples = 1000)
plan(sequential)

The results are identical whether they are computed sequentially or in parallel.

Summarize findings

The test statistics are obtained by using the generic function summary() around the resulting object:

summary(inference)
#> # A tibble: 3 × 6
#>   statistic                    estimate null_lower null_upper  p.value n_specs
#>   <chr>                           <dbl>      <dbl>      <dbl>    <dbl>   <int>
#> 1 median                          0.437    -0.0636     0.0621 0.000999      24
#> 2 share significant (positive)   24         0         10      0.000999      24
#> 3 aggregated z                   45.6      -7.57       6.86   0.000999      24

For each test statistic, the output shows the observed value (estimate), the range in which 95% of the values under the null fall (null_lower and null_upper), and the p-value, i.e., the share of curves under the null whose statistic is at least as extreme as the observed one. Here, the observed median estimate is 0.44, whereas 95% of the medians under the null lie between -0.06 and 0.06. Similarly, 24 of 24 specifications obtain a significant positive effect, which is more than would be expected if all specifications had a true effect of zero. Not a single curve under the null was as extreme as the observed curve, so all p-values are at their minimum of 1 / (1 + 1,000).

By default, the tests are two-sided. If the direction of the effect was predicted before the results were known, one-sided tests can be obtained with the argument direction:

Plot inference curve

Simonsohn et al. also suggest that the observed specification curve can be plotted against the expected under-the-null specification curves. In the figure, the estimates of each curve are ranked from lowest to highest. The grey lines represent the median as well as the 2.5th and 97.5th percentiles of the ranked curves under the null.

plot(inference)

As we can see, the observed curve is clearly different from the curves that would be expected if the true effect was zero.

For comparison: no effect in any specification

To illustrate what the results look like if there is no effect, we shuffle the dependent variable, which removes any relationship between y1 and the other variables, and repeat the analysis.

set.seed(1)
shuffled <- example_data
shuffled$y1 <- sample(shuffled$y1)

specs_null <- setup(data = shuffled,
   y = "y1",
   x = c("x1", "x2"),
   model = "lm",
   controls = c("c1", "c2"),
   subsets = list(group2 = c("female", "male")))

results_null <- specr(specs_null)

set.seed(42)
inference_null <- infer_curve(results_null, specs_null, n_samples = 1000)
summary(inference_null)
#> # A tibble: 3 × 6
#>   statistic                    estimate null_lower null_upper p.value n_specs
#>   <chr>                           <dbl>      <dbl>      <dbl>   <dbl>   <int>
#> 1 median                        -0.0473    -0.0656     0.0669   0.150      24
#> 2 share significant (negative)   2          0          9        0.251      24
#> 3 aggregated z                  -5.32      -7.02       6.81     0.128      24

Now, the observed statistics lie within the range of the statistics under the null, and the p-values are not significant. Accordingly, the observed curve lies within the curves under the null (note, however, that also in data without any effect, about 5% of such analyses yield p-values below .05 by chance):

plot(inference_null)

A note on earlier development versions

Earlier development versions of specr included this procedure under the name boot_null(). That implementation refitted each specification on too many rows, which made the curves under the null too narrow and the p-values too small. boot_null() was removed in version 1.1.0. If you used boot_null() before, please recompute your results with infer_curve().
